# UK EXIM ERP – Module Integration Status

**Reviewed:** 12 November 2026
**Source baseline:** current repository checkout, branch `codex/uk-exim-owner-login`, HEAD `3b6517f5d32b811c99d22606f46cd5b762e217cc`. The working tree already contained uncommitted Stage 2/3 work before this report.

This is a source-code inventory, not a live-data audit. No browser storage or database was read while preparing it. “PostgreSQL schema exists” means a table is declared by the repository migrations; it does not mean the UI reads or writes that table.

## Current architecture

- Next.js App Router, Next.js 16.4.5, React 19.2.4, Better Auth 1.7.18, and PostgreSQL 18.6 are the verified project versions recorded in the repository and owner-provided environment state.
- The root route checks the owner session and redirects to `/dashboard`. `/dashboard` and `/erp` are server protected. The current business workspace at `/erp` still renders the legacy LocalStorage-backed modules.
- PostgreSQL API routes found in source are `app/api/auth/[...all]/route.ts`, `app/api/products/route.ts`, and `app/api/products/[id]/route.ts`. There are no purchase, sales, stock, customer, supplier, reporting, or export CRUD routes.
- `db/migrations/001_initial_foundation.sql` declares 11 ERP tables: `companies`, `products`, `customers`, `suppliers`, `purchases`, `purchase_items`, `sales`, `sales_items`, `stock_baselines`, `stock_movement_transactions`, and `stock_movements`. The stock baseline is immutable by trigger. `002_auth_foundation.sql` declares the Better Auth user/session/account/verification/rate-limit tables and `company_memberships`.
- The only ERP DAL connected to the application API is the Product DAL. Other ERP tables are database foundation/schema only.

## Backup and migration note

`app/utils/ERPBackup.ts` defines 24 named legacy backup keys covering the core catalog/transactions, stock movement data, settings, export documents and sales numbering. The current export utility is not a PostgreSQL module migration. Keep a separate source-to-table mapping and import history for each future module. Product catalog is the only business module previously verified as imported to DEV; the other LocalStorage modules above remain pending.

## Readiness and limits

- The application is a local development preview with owner authentication and one PostgreSQL-backed Product API. It is not fully online, multi-user, or production-ready.
- Authentication/authorization is implemented for protected pages and the Product API; database row-level security is not established by this inventory.
- LocalStorage is still the operational source for most business modules. No browser data was accessed for this report.
- No migrations, database writes, browser tests, app startup, build, or deployment were performed as part of this inventory.
- The startup helper is intentionally fail-closed. During implementation inspection, `pg_ctl.exe` was not discoverable in PATH or the standard PostgreSQL 18 install location, and access to the supplied PostgreSQL data directory was denied by the inspection environment. The script has not been run; the owner should verify local PostgreSQL binary/path access before first use.
